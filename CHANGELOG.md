# @four7/cli-core

## 0.2.0-next.0

### Minor Changes

- [#4](https://github.com/schroeder-g/cli-core/pull/4) [`62067ae`](https://github.com/schroeder-g/cli-core/commit/62067ae064a96539d0e9b87a5c18839799e23e28) Thanks [@schroeder-g](https://github.com/schroeder-g)! - A program builds its commands and itself from its config: `commands(config).over<Context>()` answers `leaf`, `group`, `lazyGroup`, `notBuilt` and `program`, the config's type inferred from it. This replaces `commands<C>()` and `defineProgram<C, T>(spec)`; `program(spec)` takes the spec without its `config`.

  `leaf` takes one object, `leaf({ name, description, args, plan })`, in place of its four arguments; a leaf that takes nothing leaves `args` out. `group` takes one object too, `group({ name, description, commands })`, in place of its name, description and members.

  A planner answers a `Plan` or an `Action` as it is, or a promise of either, so it no longer wraps one in `Promise.resolve`. So do an action's `run`, a screen's `open`, a lazy group's `load`, a step's `unless.check`, a secret's `resolve`, a chosen plan's `choose` and a check's `run`.

  A program imports its parser vocabulary from `@four7/cli-core/args`: Optique's constructs, modifiers, primitives, value parsers and message helpers, `parse`, `suggest` and `getDocPage`, the types a custom value parser is written in, and cli-core's own `names`, `nameList`, `selectNamed`, `selectOne` and `timestamp`, which leave the root for it. `@optique/core` is a dependency, no longer a peer, so a program installs no Optique of its own.

  `@four7/cli-core/config` re-exports zod as `z`, beside `defineConfig`, and zod is a dependency, no longer a peer: a program writes its config's schema with cli-core's `z` and installs no zod of its own.

  `presentView` takes one object, `presentView({ io, refusal, view, props, from, presentation, onStderr })`, in place of its streams, refusal, module loader, component name, props builder and options. `view` is a closure that loads the component, `() => import('./View.tsx').then(module => module.View)`, so `props` is checked against that component and no type argument is spelled; the ended value's type comes from where the answer goes, or from the `exit` parameter's. `/screen` exports cli-core's own views ready to present, `checklistView` and `logViewer`, so a program writes `view: checklistView` in place of loading `/ui` and naming `'ChecklistView'`.

  A program registers its own views beside its config, `commands(config, { views: { notes: () => import('./Notes.tsx').then(module => module.Notes) } })`, and the binding's `present` draws any of them, or cli-core's `checklistView` and `logViewer`, by its name: `present({ io, refusal, view: 'notes', props })`, the props checked against that view's component.

  A screen belongs to its group: `group({ name, description, commands, screen })` takes the screen it opens when it is named alone on a terminal, at any depth, a lazy group's once it has loaded. `ProgramSpec.screens` and the `Screen` interface's `group` and `open` go; a program writes `screen: open` on the group in place of `screens: [{ group, open }]` on the program, and `Screen` is the function `(ctx) => number`, or a promise of it.

- [#1](https://github.com/schroeder-g/cli-core/pull/1) [`f41001e`](https://github.com/schroeder-g/cli-core/commit/f41001eaf0bb2a0a5ca52c0446c743c6177d01b1) Thanks [@schroeder-g](https://github.com/schroeder-g)! - A program gains `runMain` for its entry, `namedFiles` for files saved under names, `xdgHome` for the XDG base directories, `openUrl` and `copyToClipboard` on macOS, Linux and Windows, and in `/ui` the `Link` and `Columns` components, `hyperlink`, `rowWidth` and a `dim` label on `Labeled`, which now stacks its values in a column.

- [#1](https://github.com/schroeder-g/cli-core/pull/1) [`87a9d5e`](https://github.com/schroeder-g/cli-core/commit/87a9d5ea9a5bb0c0f1758c6865f86333ef3ac539) Thanks [@schroeder-g](https://github.com/schroeder-g)! - A program declares what needs what once and lets the user choose from it on a screen: `dependencyGraph` answers closures and dependents in the order its nodes were given, `pullingNeeds` and `pullingDependents` keep a checklist closed over it, `ChecklistView` draws the whole checklist screen in the program's words, and `chosenPlan` runs the plan a choice gives. A checklist screen's notice now clears when the cursor moves, as on every other key.

- [#1](https://github.com/schroeder-g/cli-core/pull/1) [`a49eced`](https://github.com/schroeder-g/cli-core/commit/a49ecedded9bcc8be7134e5b2d6b2c6d1fc46f16) Thanks [@schroeder-g](https://github.com/schroeder-g)! - `/process` finds a program on PATH (`findTool`) and refuses a run that lacks one (`preflight`). A program's named checks (`Check`, `loggedCheck` for programs run in turn to a log) run at once through `runChecks`, which reports each in the order given as `✓`/`✗ name detail — fix` and answers `FAILED` when any failed; `allInOrder` is the same concurrency for any other report.

- [#1](https://github.com/schroeder-g/cli-core/pull/1) [`a75e402`](https://github.com/schroeder-g/cli-core/commit/a75e402dae25a6b3e1ba570251ff277ff9cb2a2f) Thanks [@schroeder-g](https://github.com/schroeder-g)! - A `/git` entry point: `findRoot` locates a program's root without running anything, git queries read the checkout, `scratchWorktree` plans a locked scratch worktree's add and remove, and `assertGate` holds a command to its branches and a clean tree. `ProgramSpec.root` locates the root lazily, once per run, never for help or completion. `capture` takes secrets in argv and env, `captureOrFail` answers stdout or a `Failure` (or nothing for an absent pattern), and `formatCapture` prints a capture for a dry run. `/testing` makes scratch directories and repositories under an isolated git config.

- [#1](https://github.com/schroeder-g/cli-core/pull/1) [`be82380`](https://github.com/schroeder-g/cli-core/commit/be8238088efee54b6e4c093983dc988bb24aae9a) Thanks [@schroeder-g](https://github.com/schroeder-g)! - A program can keep its runs' logs and show them: `/process` writes each run behind a marker line and reads a log back by tail or by the runs since a time, and `LogFollower` follows several logs as one filtered stream. `/ui` adds `LOG_RULES`, which colours log lines, and `LogViewer`, the full-screen view of a follower.

- [#1](https://github.com/schroeder-g/cli-core/pull/1) [`72e6784`](https://github.com/schroeder-g/cli-core/commit/72e6784b0a1b0b61e3fd072c7c2cd9a8d0a42057) Thanks [@schroeder-g](https://github.com/schroeder-g)! - A program declares a list-of-names option with `names` (comma-separated or repeated, completing the names not yet typed, strict if asked), resolves the names against its items with `selectNamed` or `selectOne`, and takes a duration-or-ISO time with `timestamp`. `/testing` adds `hermetic`, a config loader that sees only the variables a test gives it, `refused` and `writeUnder`.

- [#1](https://github.com/schroeder-g/cli-core/pull/1) [`8c3d5cc`](https://github.com/schroeder-g/cli-core/commit/8c3d5cc6e1a2e6993e4f236fda601fad5fb62ae9) Thanks [@schroeder-g](https://github.com/schroeder-g)! - `/process` supervises a program's long-running processes: `supervise` runs them in the foreground and forwards a signal to their groups with a grace period, `launchDetached` leaves them running in a `recordFile` that knows each pid by its start time, and `stopRecorded` ends them by it. `stopGroup`, `awaitListening`, `listenWithRetry` and `DependencyGate` are there for a program that drives its processes itself.

  `until` and `waitForPort` answer false for a wait called off before it began, and `kill` on a detached child whose group has gone does nothing.
